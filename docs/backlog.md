# Backlog Vinyl Collection AI

Текущий этап 1 — полный локальный MVP с обычным веб-интерфейсом без AI и реальными Google Sheets. Этап 2 — публикация на собственном VPS и публичный гостевой read-only просмотр коллекции; этап 3 — AI-чат, фото, интернет-уточнения и естественный язык как дополнительный интерфейс. [README](../README.md) определяет границы; действующие спецификации определяют поведение. Номера стабильны и не задают порядок реализации. Исторические причины ниже описывают прежний прототип, а не текущие ограничения этапов. Статусы «согласовано», «требует спецификации», «реализовано», «проверено» различаются. Ни один пункт не считается реализованным только из-за включения в этап.

## 1. Дополнительный жанр

- **Этап:** 1. **Статус:** согласовано. **Требования:** [документ](data-rules.md).

- **Описание:** Принятое продуктовое решение: добавить необязательное поле `Дополнительный жанр`. Если оно заполнено, значение должно отличаться от поля `Жанр`. Поле позволяет не хранить несколько жанров списком в одной ячейке. При поиске по жанру на этапе 1 проверять оба поля: запись подходит, если жанр найден в `Жанр` или `Дополнительный жанр`.
- **Причина первоначального откладывания (история):** Первый прототип только отображал согласованные на тот момент поля. Теперь дополнительный жанр включён в модель этапа 1 и общие правила данных; это не означает завершения его реализации.

## 2. Редактирование существующей записи

- **Этап:** 1. **Статус:** требует спецификации. **Требования:** [документ](edit-record-spec.md).

- **Описание:** Редактирование записей основной коллекции и wish-list остаётся в MVP. Отдельные спецификации будут подготовлены перед реализацией этих операций.
- **Причина первоначального откладывания (история):** Сознательно отложено действующей документацией; первый прототип работает только на чтение. Это не дефект.

## 3. Удаление существующей записи

- **Этап:** 1. **Статус:** пользовательский сценарий согласован; детали интеграции требуют спецификации. **Требования:** [документ](delete-record-spec.md).
- **Описание:** Удаление выбранной записи основной коллекции или wish-list: выбор записи → подтверждение удаления → удаление → проверка результата → сообщение об успехе только после успешной проверки.
- **Причина первоначального откладывания (история):** Первый прототип не изменяет данные. Удаление остаётся в MVP; подробности интеграции определяются перед реализацией.
- **Граница:** Undo не входит в текущий MVP и вынесен в пункт 21.

## 7. Более точная идентификация прессинга

- **Этап:** не назначен. **Статус:** идея, требуется отдельное согласование. **Требования:** [документ](../README.md).

- **Описание:** Рассмотреть признаки конкретного прессинга: страна выпуска, каталожный номер и barcode. Их включение в модель и влияние на сравнение изданий согласовать отдельно.
- **Причина первоначального откладывания (история):** Текущие правила используют уже согласованный набор признаков; расширение требует отдельного решения.

## 8. Технический идентификатор записи

- **Этап:** 1. **Статус:** правила обеих моделей согласованы; реализация и миграция ещё не выполнены. **Требования:** [документ](data-rules.md).

- **Описание:** Для основной коллекции и wish-list согласован постоянный UUID в отдельной колонке `ID` Sheets, генерируемый приложением. Для существующих записей без ID предусмотрена отдельная одноразовая миграция. GET не исправляет ID; после миграции отсутствующий, некорректный или повторяющийся ID вызывает явную ошибку. Правила описаны в модели данных. Требование миграции относится к обоим документам и само по себе не разрешает изменять реальные таблицы.
- **Причина первоначального откладывания (история):** Для первого локального просмотра идентификатор не требовался. Теперь формат и хранение ID обеих моделей согласованы; реализация и проверка ещё не выполнены.

## 9. Реальное подключение двух Google Sheets-документов

- **Этап:** 1. **Статус:** согласовано. **Требования:** [документ](../README.md).

- **Описание:** Подключить основную коллекцию и wish-list, хранящиеся в двух отдельных Google Sheets-документах, через собственный API и слой доступа к данным по архитектуре README. Прямой доступ браузера к Sheets API исключён; UI использует внутреннюю модель. Контракты GET/POST/DELETE основной коллекции зафиксированы в README, маршруты API wish-list пока не определены. Общая база и специализированные модели записей, типы JSON и mapping колонок обоих документов согласованы в правилах данных.
- **Причина первоначального откладывания (история):** Первый прототип сознательно использует только локальные тестовые данные без внешних сервисов.

## 14. Расширенный поиск

## 18. Публикация приложения на собственном VPS

- **Этап:** 2. **Статус:** требует спецификации. **Требования:** [документ](../README.md).

- **Описание:** Развернуть Vinyl Collection AI на собственном виртуальном сервере владельца проекта, чтобы приложение было доступно через интернет, а не только на `localhost`. Настроить доменное имя и HTTPS, обеспечить постоянный запуск сервиса. Конфигурацию и секреты не хранить в репозитории. Предусмотреть простой процесс обновления приложения после изменений. Проект остаётся однопользовательским с точки зрения управления коллекцией.
- **Причина первоначального откладывания (история):** Текущий этап ограничен локальным прототипом; публикация и эксплуатация приложения выполняются отдельно.

## 19. Публичный режим просмотра коллекции

- **Этап:** 2. **Статус:** требует спецификации. **Требования:** [документ](../README.md).

- **Описание:** Дать другим людям возможность открыть приложение по ссылке и посмотреть коллекцию владельца. Публичный посетитель работает только в режиме **read-only**: добавление, редактирование и удаление пластинок посторонним недоступны. Публичный интерфейс должен хорошо представлять коллекцию и сам проект, позволяя использовать приложение как демонстрационный pet project — показать на собеседовании или приложить ссылку к портфолио. В дальнейшем можно добавить публичную статистику, фильтры, поиск, карточки пластинок и другие функции, интересные посетителю. **Регистрация пользователей и ведение отдельных коллекций не входят в это направление развития.**
- **Причина первоначального откладывания (история):** Текущий прототип предназначен для локального просмотра тестовых данных; публичное представление реальной коллекции и разграничение доступа относятся к будущему этапу.

- **Граница:** На этапе 2 согласован только гостевой просмотр. Видимые гостю поля и авторизация владельца требуют согласования; статистика, публичный поиск, карточки и другие расширения не включены автоматически.

## 21. Undo после удаления

- **Этап:** будущий, не назначен; не входит в текущий MVP. **Статус:** идея UX-улучшения, требует спецификации.
