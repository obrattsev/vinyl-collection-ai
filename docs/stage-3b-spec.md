# Пакет 3B — согласованный контракт

Статус: реализовано локально в feature/stage-3b; автоматические тесты и self-review выполнены, основная функциональность и UX-коррекция прошли local acceptance и приняты владельцем. Владелец разрешил закрытие принятого общего пакета 3B + 3C: commit, push, PR, merge и deployment из актуального main после чистых проверок. Presentation polish выполняется следующим подэтапом [3C](stage-3c-presentation.md) в той же рабочей ветке.

## Responsive presentation

Один интерфейс: desktop table → compact list при ширине ≤1120 px → bottom sheet на основе native dialog. Breakpoint стартовый, подлежит визуальной проверке владельцем. Один displayedRecords и activeSort для обоих представлений. Resize не вызывает GET, не сбрасывает поиск/сортировку. Краткая запись содержит три строки: исполнитель → альбом → «год · основной жанр». Год не вынесен к правому краю. Нажатие открывает только detail. Guest видит девять публичных полей; owner — пользовательские поля своей модели без UUID. Detail очищается при смене роли.

Owner открывает существующие редактирование/удаление/перенос из detail без вложенных modal. После успеха — обновлённый список; после отмены — focus исходной записи либо области результатов. Native dialog обеспечивает модальность, клавиатурную навигацию и Escape; есть явная кнопка закрытия с теми же height/min-height/padding, что у detail actions.

Mobile sorting: компактная строка «Сортировка», select поля по содержимому и непосредственно рядом кнопка ↑/↓ с accessible label; оба control высотой 44 px, на узком экране группа переносится без переполнения. «По умолчанию» означает activeSort=null, Исполнитель ASC → Год альбома ASC, кнопка направления отключена. Desktop headings управляют тем же состоянием.

CSV сохраняет контракт 3A независимо от viewport: guest 9, owner Collection 9, owner Wish-list 10 колонок; без UUID и технических полей. Строки/порядок определяются поиском и сортировкой.

## Сообщения об ошибках

POST /api/bug-reports доступен guest/owner только с проверкой same-origin. Остальные изменяющие API сохраняют owner+CSRF. Нет публичного GET reports и inbox. Клиент передаёт только text и section (collection/wishlist), максимум 2000 Unicode code points, непустой текст; body ≤16 KiB. Сервер создаёт UUID и UTC timestamp. Версия читается один раз при старте из существующего файла RELEASE в корне deployment; при отсутствии локально null. Git при запросах не нужен.

Отдельный Google Sheets-документ: ID | Создано UTC | Сообщение | Раздел | Версия приложения. Spreadsheet ID и sheet name задаются только серверной конфигурацией, документ обязан отличаться от Collection и Wish-list. Значения пишутся как stringValue, без интерпретации формул. Успех — только после перечитывания и проверки записи. Неопределённый результат не повторяется автоматически.

Лимиты в памяти одного процесса: 3 попытки / 15 минут / IP и 50 попыток / час суммарно, отдельные от login/GET, 429 + Retry-After. Очередь reports отдельная и ограниченная. Перезапуск сбрасывает счётчики. IP не сохраняется. Не собираются пароль, cookies, session/CSRF, IP, URL/query, referrer, записи коллекций, формы CRUD, stack traces, User-Agent. Текст report не логируется. Нет вложений/CAPTCHA.

Форма доступна в обоих разделах/ролях/представлениях: текст, счётчик, точный helper «Не указывайте пароли и личные данные», очистка/отправка и × с accessible label «Закрыть», состояния отправки/успеха/ошибки. Ошибка или неопределённый результат сохраняют текст; подтверждённый успех очищает draft, закрывает dialog и показывает transient status «Сообщение отправлено» на 5 секунд без второго dialog.

Реальные Sheets и production не изменяются. Подключение нового документа требует отдельного действия/подтверждения владельца. Local acceptance использует синтетические записи и reports в памяти.

## Детали реализации и ошибки

Лимитер использует скользящие окна, хранит не более 50 допущенных попыток за последний час. Неверный JSON/валидация и недоступное хранилище расходуют попытку; запросы, уже отклонённые лимитером, не продлевают окно. Same-origin проверяется до limiter. IP определяется существующим механизмом доверенного loopback nginx; forwarded headers от остальных peers игнорируются.

Очередь reports отдельная от CRUD, не более четырёх выполняющихся/ожидающих запросов. Превышение — 503 REPORT_BUSY. Никаких автоматических retries. Репозиторий перечитывает reports для валидации заголовков/UUID и проверки сохранности прежних строк; при большой истории стоимость чтения растёт. Публичного endpoint чтения нет.

| Ответ | Значение |
| --- | --- |
| 201 `{id}` | Запись подтверждена; текст не возвращается |
| 400 INVALID_REQUEST | JSON/content type/body limit |
| 400 INVALID_REPORT | Непустой текст до 2000 code points, валидный Unicode, точные поля/section |
| 403 FORBIDDEN | Origin/Host/Fetch-Site не прошли проверку |
| 405 METHOD_NOT_ALLOWED | Reports поддерживает только POST |
| 429 RATE_LIMITED | Retry-After в секундах |
| 503 REPORT_NOT_CONFIGURED | Нет опциональной конфигурации |
| 503 REPORT_SOURCE_UNAVAILABLE | Не удалось проверить источник до записи |
| 503 REPORT_BUSY | Очередь занята |
| 500 RESULT_UNCONFIRMED | После попытки записи результат не подтверждён, ответ содержит серверный id |

Пользовательский текст не обрезается автоматически. Счётчик считает Unicode code points, включая emoji, а не UTF-16 units или grapheme clusters; при превышении отправка отключена. Простое закрытие через ×/Escape сохраняет текст до перезагрузки/перехода на другую страницу, localStorage не используется. «Очистить» очищает draft, статус и счётчик, не закрывает dialog и возвращает focus в textarea. Во время POST поля/повторная отправка/очистка/закрытие формы отключены. Успех закрывает форму, очищает textarea и показывает короткий status вне dialog. Ошибка сохраняет draft; повторную отправку решает пользователь с предупреждением о возможном дубле.

Resize закрывает открытый detail и возвращает focus в доступное представление, не изменяя данные/поиск/activeSort. Возврат из owner CRUD ищет запись по UUID только внутри UI; UUID не показывается. Guest detail использует только публичные поля.
