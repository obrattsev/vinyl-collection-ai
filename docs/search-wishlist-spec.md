# Просмотр и поиск в wish-list

Статус: согласовано для интерфейса без AI. Этап: 1.
Связанные документы: [правила данных](data-rules.md), [будущий AI](ai-stage.md).

## Поведение

Получение всего списка возвращает все строки без подтверждения. Поиск и просмотр ничего не изменяют ни в одном документе. При интеграции UI получает `WishlistRecord` через собственный API и слой доступа к данным из отдельного Google Sheets-документа wish-list. Прямого обращения браузера к Sheets нет; маршруты API wish-list ещё не определены.

Пользователь задаёт поле, значение и для текста явный режим «точное совпадение» или «содержит». Автоматического угадывания режима нет. Доступны Исполнитель, Альбом, Жанр (оба жанра), Лейбл, Год альбома, Год пластинки, Тип издания, Примечание, Ссылка на онлайн-магазин.

Текст сравнивается после общей нормализации. «Содержит» — поиск подстроки. Для годов, типа издания, даты и цены (где такие поля есть) — только точное совпадение. Диапазоны не поддерживаются. Все заданные критерии применяются одновременно (И); внутри критерия жанра совпадение любого из двух жанров достаточно (ИЛИ).

Пустой критерий (в том числе текст, пустой после общей нормализации) означает, что фильтр по соответствующему полю не применяется. Он не означает поиск записей с пустым полем. Если непустых критериев нет, возвращается весь список.

Сначала проверить форматы непустых критериев. При корректных критериях выполнить поиск без дополнительного подтверждения. Применять только техническую нормализацию по общим правилам данных; смысловое исправление написаний и AI-подобные проверки относятся к этапу 3. Кнопка отмены отбрасывает неподтверждённый проект критериев; можно начать новую операцию.

## Результат

Все подходящие строки, каждое физическое издание отдельно, в таблице:

Исполнитель | Альбом | Жанр | Дополнительный жанр | Лейбл | Год альбома | Год пластинки | Тип издания | Примечание | Ссылка на онлайн-магазин

Пустой полный список: «Wish-list пуст».
Нет совпадений поиска: «По поисковому запросу записей в wish-list не найдено».

Технический UUID входит в каждую запись `WishlistRecord`, но не обязан отображаться в таблице и не добавляет критерий поиска. JSON соответствует общему mapping: все применимые ключи присутствуют, пустые необязательные значения — `null`. Чтение не создаёт и не исправляет ID или другие обязательные значения. Нарушения целостности после миграции приводят к явной ошибке по общим правилам данных, а не к пустому списку.

## Приёмка

Возвращены все и только соответствующие записи, применены все выбранные критерии, форматы интерпретированы корректно. Исходные данные не изменились. Пустой список отличается от отсутствия совпадений; ошибка чтения не отображается как пустой список.

Поиск по фотографии и распознавание свободных команд — этап 3.
