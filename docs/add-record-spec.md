# Добавление в коллекцию

Статус: согласовано для интерфейса без AI; реализовано для основной коллекции. Контролируемый реальный acceptance записи пройден. Этап: 1.
Связанные документы: [правила данных](data-rules.md), [будущий AI](ai-stage.md), [backlog](backlog.md).

## Общие действия интерфейса

Обе вкладки используют одну навигацию непосредственно под логотипом и названием. В формах добавления и переноса «Отмена» слева, прозрачная secondary; на просмотре проекта «Исправить» по центру, также secondary; подтверждающее действие справа, primary. Подтверждение удаления использует ту же раскладку с destructive справа. Общие CSS-классы применяются к обоим разделам. Кнопка открытия добавления в обоих разделах — «Добавить пластинку».

## Сценарий

1. Пользователь открывает добавление в явно выбранном разделе «Коллекция». Целевая коллекция видна в форме и при подтверждении; технические ID документа и названия листов Google Sheets UI не использует.
2. Вручную заполняет пользовательские обязательные и выбранные необязательные поля из правил данных, включая дополнительный жанр. Существующие написания предлагаются как подсказки, не применяются автоматически.
3. Приложение проверяет обязательность и форматы, нормализует значения только для сравнения. Проверить дубли по общим правилам: возможное совпадение с неизвестными признаками показать как предупреждение с найденными записями и возможностью подтвердить добавление; подтверждённый дубль издания блокирует добавление.
4. Показывает полный проект новой строки. Пользователь может исправить данные, отменить операцию или подтвердить проект. Исправленный проект проверяется и подтверждается заново.
5. После подтверждения повторно проверяет форматы и дубли по актуальным данным.
6. Приложение генерирует постоянный UUID по [общим правилам данных](data-rules.md#постоянный-id-записей); пользователь не задаёт ID при обычном добавлении. Добавляет ровно одну строку в конец целевого документа, не перезаписывая существующие строки.
7. Перечитывает добавленную строку и сравнивает с подтверждённым проектом. Сообщает успех только после проверки.

При интеграции UI передаёт данные в JSON body `POST /api/collection`; запись выполняется через собственный API и слой доступа к данным. Успешный ответ — `201 Created` и фактически созданный `CollectionRecord` по общему mapping, включая ID. Пользовательские значения сверяются с подтверждённым проектом; назначенный ID — с записанным ID. Базовые ошибки определены в [контракте API](../README.md#архитектура-доступа-к-данным-и-api).

## Критерии приёмки

- Все пользовательские общие поля и поля целевого документа доступны; обязательные поля заполнены, форматы соблюдены.
- Подтверждённый дубль не добавляется даже после подтверждения. Неизвестные признаки издания дают предупреждение с возможностью подтвердить добавление по [общим правилам](data-rules.md#потенциальные-дубли-при-добавлении).
- До подтверждения и после отмены запись не выполняется.
- Успешное добавление создаёт одну строку в конце, совпадающую с проектом; существующие данные обоих документов сохраняются.
- Ошибки и неопределённый результат записи не выдаются за успех; применяется согласованное поведение ниже.

Фото, AI-команды и интернет-уточнение перенесены на этап 4. Перенос покупки из wish-list не является частью этой операции.

## Ввод и обратная связь формы

- Жанр и Дополнительный жанр выбираются из одного закрытого [справочника](../src/genres.mjs). Оба поля сохраняют необязательность; свободного ввода и варианта «Другое» нет. Заполненные жанры должны различаться по общим правилам.
- Дата покупки вводится цифрами, не более восьми; дефисы YYYY-MM-DD подставляются автоматически. Недопустимые символы и избыточная длина при вводе или вставке отклоняются. Неполная или несуществующая календарная дата не допускается при подтверждении; серверная проверка сохраняется.
- Цена вводится неотрицательной суммой в рублях: цифры, один десятичный разделитель (точка или запятая), до двух знаков копеек. Запятая преобразуется в точку. Буквы, знаки, экспонента, лишние разделители и знаки копеек, включая вставку, отклоняются. В JSON отправляется число, пустое поле — null, 0 — бесплатно.
- При ошибке показывается «Проверьте заполнение обязательных полей, формат даты и цены.». Ошибочные поля выделяются красной рамкой и текстовой подсказкой, связанной через ARIA; после исправления признак ошибки снимается. Допустимость записи определяет общая модель, используемая и сервером.
- После успешного добавления или удаления список перечитывается; ранее начатый GET не может заменить результат более нового чтения или отменить обязательное обновление при неопределённом результате записи.

## Неопределённый результат основной коллекции

После попытки записи, в том числе при потере ответа Google, приложение перечитывает коллекцию и проверяет новый UUID, все подтверждённые значения и сохранность существующих записей. Только подтверждённый результат даёт успех. Иначе — `RESULT_UNCONFIRMED` и сообщение «Результат операции не подтверждён»; пользователь должен обновить коллекцию перед дальнейшими изменениями.

Автоматического повтора POST или записи в Sheets нет. Отсутствие строки при чтении после timeout не доказывает, что исходная запись не завершится позже. Новый проект не является автоматическим продолжением старого.
