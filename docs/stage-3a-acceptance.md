# Локальная acceptance 3A

Статус: 216 автоматических unit/integration/UI regression tests пройдены; локальная acceptance всего пакета успешно завершена и принята владельцем. Независимый финальный review не выявил подтверждённых замечаний. Во время разработки production и реальные Sheets не изменялись. Browser automation не смогла открыть локальную страницу: инструменту недоступна обязательная проверка политики доступа. Это не результат проверки браузерного UI.

## Изолированный запуск

В репозитории на ветке feature/stage-3a, с Node 24 и уже установленными зависимостями:

```sh
cd /Users/obrattsev/vinyl-collection-ai
node scripts/local-acceptance.mjs
```

Если node отсутствует в PATH на текущем Mac:

```sh
/Users/obrattsev/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node scripts/local-acceptance.mjs
```

Открыть http://127.0.0.1:8013/collection. Пароль тестового owner: `local-acceptance-only`. Это публичный пароль исключительно изолированного стенда, не production credential. Сервер слушает только loopback, не читает .env, не подключается к Google и хранит только вымышленные записи в памяти. Остановка Ctrl+C; перезапуск восстанавливает исходный набор. Если порт занят предыдущим экземпляром, сначала остановить его.

## Сценарий

1. Guest: «Показать всю коллекцию». Ожидаются Alpha / First (1980), Alpha / Second (1990), Zebra / Late (2000). Убедиться, что Alpha / First и Alpha / Second стоят вместе в хронологическом порядке. Проверить подписи «Показать всю коллекцию» и «Показать весь wish-list». Проверить восемь сортируемых заголовков, ASC/DESC, отсутствие сортировки у Примечания. У Года пластинки пустое значение всегда последнее.
2. Поиск artist=Alpha возвращает две строки. Ручной порядок сохраняется после поиска и полного просмотра. «Очистить» удаляет результат и сбрасывает порядок. Поиск New Age / Various работает; проверить также жанр в дополнительном поле Wish-list.
3. Скачать полный список и результаты поиска в обоих направлениях сортировки. В CSV те же строки и порядок, русские заголовки, девять публичных колонок, без UUID и сведений о покупке. Текст с кавычками/переносами сохраняется в одной ячейке; =1+1 не исполняется как формула. Пустой результат не скачивается.
4. Войти. У Zebra / Late открыть «Редактировать»: жанр Legacy genre сохранён, дата 03-09-2026. Изменить примечание, цену на 0, дату на 29-02-2024, очистить магазин. Просмотреть полный проект с «Было → Стало», нажать «Исправить», повторно просмотреть и подтвердить. Открыть запись снова: значения сохранены; в Network PUT дата 2024-02-29, price=0, магазин=null, UUID прежний и не в body, есть If-Match. Отдельно проверить отмену без PUT.
5. Ввести 29-02-2023, неполную дату, буквы/лишние цифры, проверить вставку и Backspace/Delete около дефисов. Невозможная дата не подтверждается; буквы/лишние цифры отклоняются. Пустая дата допустима. Проверить сохранение Legacy genre без изменения и последующую замену на New Age/Various.
6. Выполнить поиск album=Late и выбрать ручную сортировку. Редактированием заменить Late на другое название: после сохранения результат пуст, поиск не сбрасывается. Полный просмотр возвращает запись с новым названием и прежней ручной сортировкой.
7. Wish-list: проверить подпись «Ссылка», редактирование и очистку ссылки. Owner CSV имеет десять видимых колонок со Ссылкой, без UUID; Collection по-прежнему девять без покупок. Выйти: результаты/экспорт очищаются; после нового просмотра Wish-list имеет девять колонок без Ссылки и действий.
8. Конфликт: войти, открыть одну запись в двух вкладках. В первой подготовить preview со своим примечанием. Во второй сохранить другое значение лейбла. Подтвердить первую: 409, собственный ввод остаётся, актуальный лейбл показан отдельно, автоматического PUT нет. Нажать «Пересмотреть…», вручную выбрать нужные значения, заново просмотреть и подтвердить. Проверить, что отмена конфликта ничего не записывает.
9. Дубли: у Alpha / Second сменить album на First и recordYear на 2024; при одинаковых label/editionType подтверждённый дубль блокируется. Очистить label: остаётся предупреждение, которое допускает подтверждение. Для межсписочной проверки отредактировать Wish-list под полное издание Collection: блокируется. Делать это только на стенде.
10. Регрессии: добавить вымышленную запись, отменить/подтвердить удаление; перенести Wish Alpha в Collection с датой 29-02-2024 и ценой 0. Убедиться, что исходник удалён только после создания, дата в preview DD-MM-YYYY. Проверить две страницы при узком окне, доступность кнопок и горизонтальную прокрутку таблицы.

Timeout, RESULT_UNCONFIRMED, сбой перечитывания, сохранность соседних строк/неизвестных колонок, очередь, stale GET и auth/CSRF проверяются автоматическими тестами с подменённым источником. Стенд в памяти не симулирует ошибки Google и не проверяет реальный Sheets write. Намеренно повреждать реальные данные для проверки не требуется.

## Технические проверки

```sh
npm test
git diff --check
```

Новые тесты: edit-record.test.mjs, edit-sheets.test.mjs, stage-3a-ui.test.mjs. Существующие тесты сохранены; ожидания маски даты, числа жанров и списка защищённых методов обновлены под согласованный контракт.

Владелец разрешил закрытие 3A после чистого финального review: commit → push → PR → merge → deployment из main по существующему runbook. Production browser acceptance пользовательских функций проводится владельцем отдельно; реальные изменяющие acceptance-операции агентом не выполняются.

Дополнительная проверка группировки: на изолированном стенде добавить по три записи David Bowie (1969, 1970, 1971) и четыре Pink Floyd (1967, 1969, 1970, 1971), задавая общий жанр Jazz и различные названия альбомов. В полном списке и поиске Jazz блок David Bowie должен целиком предшествовать Pink Floyd; внутри каждого блока годы возрастают. Регистр и лишние пробелы в имени не разрывают группу. После ручной сортировки нажать «Очистить» и повторить поиск — базовый порядок восстановится. Равные исполнитель/год сохраняют исходный порядок. Пустой albumYear тестируется только в presentation unit-тесте: UI/API по-прежнему требуют корректный год и не позволяют создать такую запись.
