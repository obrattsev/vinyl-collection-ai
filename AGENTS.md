- Roadmap определяется docs/backlog.md. Этап 1 — завершённый локальный MVP без AI на реальных Google Sheets; acceptance обеих коллекций пройден. Этап 2 завершён по подтверждению владельца; 3A реализован и принят владельцем по итогам локальной acceptance, 3B принят по local acceptance; 3C Presentation polish и уточнение даты DD.MM.YYYY приняты владельцем, 3B/3C завершены, production Bug Reports проверен; 3D Favorites/Covers/Daily Quote реализован и развёрнут, initial backfill завершён; local acceptance принята, финальная визуальная production acceptance ожидается; отчёт docs/stage-3d-production.md; 3E Streaming принят владельцем по local acceptance; финальные Add Cover и mobile Transfer variant также приняты; commit/push/PR/merge/deploy разрешены владельцем; этапы 4–5 не начаты: этап 2 — VPS → аутентификация owner → публичный read-only просмотр collection/wish-list; этап 3 — развитие без AI, включая редактирование; этап 4 — PostgreSQL и многопользовательский режим (4A–4F); этап 5 — AI, включая Dynamic Daily Quote с curated fallback. Порядок задач этапа 2 отражает roadmap, а не обязательную техническую последовательность.
- Соблюдать статусы документов. Не реализовывать неподтверждённые продуктовые решения; при неоднозначности спрашивать владельца. Продолжать независимую согласованную работу.
- Доступ к данным: UI → собственный API → слой доступа к данным → Google Sheets. Не обращаться к Sheets API из браузера: UI использует внутреннюю модель без деталей Sheets и авторизации Google. Контракты — в README, общие модели, JSON mapping, правила UUID обеих коллекций, миграции и целостности данных — в docs/data-rules.md.
- Общие правила данных находятся в docs/data-rules.md; не дублировать их расходящимися версиями.
- Работать небольшими итерациями в отдельных Git-ветках; сохранять чужие и незакоммиченные изменения.
- Выполнять тесты, соответствующие изменению, проверять git diff --check и содержимое diff; сообщать результаты review и ограничения.
- Различать «согласовано», «реализовано» и «проверено». Завершённость этапа 1 не означает реализации будущих задач этапов 2–5.
- Не хранить ключи и секреты в Git или браузерном коде. Подключение реальных таблиц и изменения данных должны соответствовать согласованному сценарию подтверждения.
- Обычный GET не создаёт и не исправляет ID. Текущим таблицам миграция не нужна; legacy-миграция — условная отдельная работа вне этапов при появлении записей без UUID. Приложение нельзя делать публично доступным до защиты всех изменяющих данные коллекций API аутентификацией owner; выбраны пароль owner, серверная сессия и CSRF; актуальный контракт и acceptance — docs/stage-2-auth.md.
- Не расширять продукт, не публиковать приложение и не включать AI раньше согласованного этапа.
