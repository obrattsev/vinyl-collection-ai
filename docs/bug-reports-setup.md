# Подключение Bug Reports Google Sheet (3B)

Статус: production документ создан, подключён и проверен; долг 3B закрыт по подтверждению владельца. Acceptance-сообщение проверено и удалено. Ниже сохранена инструкция настройки/восстановления. Для local acceptance reports хранятся в памяти процесса.

## Действия владельца после отдельного подтверждения

1. Создайте новый **отдельный** Google Sheets-документ, например «Vinyl Collection — Bug Reports». Не добавляйте лист reports в документы Collection/Wish-list.
2. Назовите вкладку `Bug Reports`. В первой строке A1:E1 вставьте пять заголовков (можно скопировать строку ниже, разделители — табуляция):

```text
ID	Создано UTC	Сообщение	Раздел	Версия приложения
```

3. Не заполняйте ID и timestamp вручную; не вставляйте реальные тестовые сообщения. Сохраните заголовки без дублей и лишних пробелов. Лист может быть пустым после заголовков.
4. Через «Настройки доступа» предоставьте существующему service account приложения право «Редактор» только к этому новому документу. Email service account можно посмотреть в Google Cloud → IAM и администрирование → Сервисные аккаунты. Не публикуйте документ по ссылке и не передавайте JSON-ключ/пароль в чат.
5. Возьмите spreadsheet ID из адреса нового документа — часть между `/d/` и `/edit`. Он должен отличаться от обоих существующих spreadsheet ID.
6. Сообщите о готовности и отдельно согласуйте подключение. В серверный environment вне Git потребуется добавить:

```dotenv
BUG_REPORT_SPREADSHEET_ID=<ID нового документа>
BUG_REPORT_SHEET_NAME=Bug Reports
```

Обе переменные обязательны вместе; ошибочное совпадение с документом коллекции блокирует запуск. Google credentials используются прежние, scope spreadsheets прежний. Новых credentials, миграции коллекций, nginx/systemd/WireGuard/SSH изменений не требуется. Применение production env и перезапуск приложения выполняются только в отдельно согласованном deployment.

## Версия и чтение

Версия берётся один раз при старте из файла `RELEASE` в корне активного релиза (существующий deployment marker с полным commit SHA). Файл должен содержать SHA до запуска процесса. Runtime Git не нужен. Если файл отсутствует или не содержит SHA, версия записывается пустой (`null`), как на локальном acceptance.

Владелец читает сообщения непосредственно в новом Google Sheet. Публичного API/inbox нет. Текст записывается как строка даже при начале с `=`, `+`, `-` или `@`. Серверный успех требует последующего чтения и сверки всех пяти полей и прежних записей. Неопределённый результат может означать уже сохранённую запись; автоматического повтора нет.
