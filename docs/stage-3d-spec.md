## Модель и API

Актуальный Sheets mapping — [общие правила данных](data-rules.md). Collection получает `coverId: string | null` и `favorite: boolean`; Wish-list только `coverId`. Пустое значение favorite читается как false без переписывания строк. Заголовки новых колонок обязательны; их отсутствие не скрывается fallback. Реальные документы в ходе local implementation не изменялись.

| Операция | Body | Результат |
| --- | --- | --- |
| `PUT /api/collection/:id/cover`, `PUT /api/wishlist/:id/cover` | Бинарный JPEG/PNG/WebP, соответствующий Content-Type | Полная проверенная запись, 200 |
| `DELETE /api/collection/:id/cover`, `DELETE /api/wishlist/:id/cover` | Нет | Полная проверенная запись с coverId=null, 200 |
| `PATCH /api/collection/:id/favorite` | Только `{ "favorite": true/false }` | Полная проверенная запись, 200 |
| `GET/HEAD /media/covers/:coverId/thumb.webp` или `image.webp` | Нет | Нормализованное публичное изображение; нет directory listing |

Все изменения требуют owner session, точный Origin, CSRF и If-Match по всей актуальной записи. Общая очередь используется вместе с metadata CRUD и transfer. Коды: 400 неверный ввод, 404 отсутствующая запись/изображение, 409 RECORD_CHANGED, 413 превышение тела, 415 неподдерживаемый MIME, 503 отсутствие хранилища/занятый обработчик, 500 RESULT_UNCONFIRMED. Успех только после перечитывания Sheets, сверки результата и сохранности соседей. Слепого retry, rollback и автоматического повторного upload нет. При конфликте/неизвестном результате UI сохраняет окно и требует закрыть его и явно обновить список.

POST/PUT metadata сохраняют прежний набор пользовательских полей; coverId/favorite в этих body отклоняются. Создание задаёт null/false, редактирование сохраняет текущие значения. Sheets update записывает только изменённые ячейки: поздний metadata/favorite-запрос не может повторно присоединить старую обложку. Ревизии включают новые поля. Favorite и cover не участвуют в дублях или базовом порядке; cover не участвует в поиске.

Guest получает 9 прежних публичных полей + `cover: null | {thumbnailUrl,imageUrl}`, а Collection также `favorite`. UUID записи, coverId как отдельное поле, покупки и storeUrl не раскрываются. UUID файла в публичном URL — отдельный идентификатор ресурса, не UUID записи. Приватность самих обложек не предполагается.

## Хранилище и целостность

`COVERS_DIR` — абсолютный путь вне releases, production target `/var/lib/vinyl-collection-ai/covers`. Исходные файлы, имена и EXIF не сохраняются. Sharp 0.35.5 декодирует и нормализует одиночное изображение в WebP: большая сторона до 1200 px, thumbnail до 144 px, без увеличения исходника. Максимумы входа: 10 MiB, 16 млн пикселей; анимация и прочие форматы отклоняются. JPEG/PNG/WebP проверяются декодером, одного MIME недостаточно. **HEIC/HEIF отложены по решению владельца**: готовая библиотека не включает необходимый HEVC codec; отдельная тяжёлая сборка не входит в 3D.

Одновременно допускается один cover-request (чтение тела + общая очередь + обработка), timeout при бездействии загрузки 15 секунд, sharp concurrency=1/cache memory=16 MiB. Это ограничивает нагрузку, но не является измерением RSS на Linux/VPS: production-проверка в MemoryMax=512M остаётся частью отдельного deployment.

Файлы сначала полностью готовятся во временном каталоге, затем каталог переименовывается в UUID. Права новых каталогов 0700, файлов 0600; существующие права не меняются. Перед попыткой записи ссылки создаётся persistent `.holds/<uuid>` с обеими ссылками. Подтверждённый результат позволяет снять hold; ошибка/неизвестный результат/падение процесса оставляют обе версии, включая после restart. Неудача подготовки не меняет coverId.

Удаление сначала подтверждает очистку ссылки. Старый файл удаляется только после успешного чтения **обеих** коллекций и отсутствия ссылки либо hold. Ошибка чтения/повреждённый hold запрещает физическую очистку, но не отменяет уже подтверждённое изменение записи. Transfer новой записи копирует coverId, задаёт favorite=false и держит hold до подтверждения append; частичный/неизвестный перенос не даёт удалить нужный файл. При выборе существующей Collection-записи её cover/favorite сохраняются.

Сомнительные и оставшиеся после удаления самой записи файлы автоматически не собираются. Они могут занимать место до отдельной ручной сверки; нельзя удалять `.holds` или считать возраст/отсутствие строки доказательством неуспеха. Sweep/cron здесь нет. Общая очередь предполагает один процесс приложения; прямое параллельное изменение этих ссылок в Sheets не заменяет транзакцию и не поддерживается как способ управления обложками.

## Цитаты и заголовки

Источник `prototype/data/music-quotes.json`: массив `{id,artist,song,quote,section}`, section=collection/wishlist/both. Каталог содержит 10 предоставленных владельцем цитат с устойчивыми человекочитаемыми ID `go-*`, у всех section=both. Текст, пунктуация, маскировка и переносы строк сохранены дословно, без интернет-поиска и нормализации. Стенд использует тот же каталог, что используется в production; тесты алгоритма сохраняют вымышленные fixtures, точность каталога отдельно проверяется fingerprint.

Выбор по локальной календарной дате браузера, упорядоченным ID и отдельному offset раздела; refresh не меняет выбор. Следующий локальный день меняет индекс; для реальной смены нужен минимум 2 допустимых элемента в разделе. Таймер до следующей локальной полуночи + focus/visibility обновляют открытую страницу, без cron/server scheduler/Math.random. Пустой или недоступный источник скрывает блок; некорректные элементы пропускаются. Рекомендация 100 символов не является ограничением validator.

Большие визуальные заголовки удалены, semantic h1 сохранён visually-hidden с aria-labelledby секции. Quote block имеет светло-серый фон, небольшой radius и padding, без рамки/тени. `white-space: pre-wrap` сохраняет переносы без line-clamp; attribution выделен отдельным меньшим sans-serif текстом. Цитата компактна, не hero, надписи «Цитата дня» нет. Dynamic/AI источник — этап 5.

## Перед отдельным production deployment

Владелец разрешил добавление только заголовков `Обложка ID` в обоих документах и `Избранное` в Collection, без массового изменения строк; резервную копию данных/схемы и проверку чтения. Не запускать 3D на старой схеме.

Подготовить persistent каталог с владельцем приложения и COVERS_DIR во внешнем env. Проверить разрешение записи в существующей systemd sandbox без расширения архитектуры unit. Проверить установку Linux sharp optional dependencies из lockfile, decoding и RSS под MemoryMax=512M. Проверить текущий nginx body limit: 10 MiB приложения не означает автоматически такой же лимит proxy; любые необходимые изменения согласовать отдельно.

Backup/restore **всего** covers, включая `.holds`, обязателен: остановить только приложение, сохранить согласованный снимок Sheets/каталога и его владельца/режимов; восстановление сначала испытать в отдельном каталоге, проверить нормализованные файлы и ссылки. При rollback старые файлы, требуемые восстановленным Sheets snapshot, должны быть восстановлены из того же набора. Требования выполнены при deployment 30.09.2026; результаты — в [production-отчёте](stage-3d-production.md). VPS/nginx/WireGuard/SSH/Zabbix/firewall/HTTPS в local implementation не затрагиваются.
