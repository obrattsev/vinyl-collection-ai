# Этап 2: программная часть и локальная acceptance

Статус: программная часть и последние UX-корректировки прошли локальную acceptance владельца. Финальный review и автоматические тесты выполнены перед фиксацией. Этап 2 целиком не завершён: deployment, домен, HTTPS и внешняя acceptance ещё впереди. Настройки существующего VPS/VPN не изменялись.

## Доступ и API

Один owner без регистрации. Guest сразу видит интерфейс коллекции без загруженного списка, может открыть wish-list и искать. Девять полей публичной проекции определены в data-rules.md; идентификаторы гостю не нужны. Owner получает полные прежние модели. После входа UI показывает добавление/удаление/перенос, но не запрашивает записи автоматически; после выхода закрывает формы и очищает приватные данные. Авторизация всегда выполняется сервером, а не браузером.

| Endpoint | Контракт |
| --- | --- |
| GET /api/auth/session | 200 `{role:"guest"}` или `{role:"owner",csrfToken,expiresAt}`; expiresAt — абсолютный Unix timestamp в миллисекундах |
| POST /api/auth/login | JSON `{password}`; 200 owner/session и Set-Cookie; неверный пароль — 401 INVALID_CREDENTIALS |
| POST /api/auth/logout | Owner cookie + X-CSRF-Token; 200 `{role:"guest"}`, отзыв серверной сессии и удаление cookie; истёкшая сессия — 401 AUTH_REQUIRED |
| GET /api/collection, GET /api/wishlist | Guest — публичная проекция; owner — прежние полные модели; массив и прежние ошибки источника сохраняются |
| Все существующие POST/DELETE/transfer | Owner cookie + X-CSRF-Token + точный Origin; остальные прежние body/If-Match/ответы неизменны |

Все ответы `Cache-Control: no-store`. GET данных содержит `X-Access-Role: guest/owner` для обработки истечения сессии между запросами. Cookie и CSRF не хранятся в localStorage. Cookie автоматически отправляется браузером; JS получает только CSRF из auth endpoint. Ошибки доступа: `401 AUTH_REQUIRED`, `403 FORBIDDEN`, `429 RATE_LIMITED` с `Retry-After` в секундах. Ошибки не содержат пароль, хеш, cookie или внутренние исключения. Логин защищён проверкой Origin и JSON content type; остальные изменяющие операции дополнительно требуют CSRF. Будущие небезопасные HTTP-методы также проходят общий owner guard до dispatch; auth endpoints — явные исключения с собственной политикой.

## Пароль и сессии

Хеш: scrypt N=131072, r=8, p=1, случайная соль 16 байт, результат 64 байта. Формат конфигурации строго проверяется; plaintext не принимается. Проверка асинхронна, сравнение constant-time. Одновременно выполняется не более одной дорогой проверки пароля (~128 MiB памяти scrypt); остальные попытки получают 429. Исходный пароль существует только кратковременно при вводе/проверке, не сохраняется и не логируется.

Случайные session ID и CSRF по 32 байта; cookie `HttpOnly; SameSite=Lax; Path=/; Max-Age=604800`. Production добавляет `Secure` и имя `__Host-vinyl_session`; локально имя `vinyl_session`. Нет Domain. Максимум 7 дней с момента login и 24 часа без запросов с действительной сессией. Проверки выполняются сервером при запросах; cookie сама по себе не доказывает действительность сессии. После рестарта все сессии исчезают. Login заменяет представленную старую сессию, logout отзывает её. Максимум 32 сессии; новый вход сверх лимита отзывает самую старую. Удаление просроченных записей выполняется при запросах.

Смена пароля: создать новый файл хеша, заменить конфигурацию безопасным способом и перезапустить приложение; это отзывает все сессии. Восстановление через email, регистрацию и MFA не добавляли. Исчезновение сессии не повторяет неподтверждённую операцию автоматически. Уже принятая до logout операция может завершиться; её исход следует проверять по существующим правилам результата записи.

## Environment

| Переменная | Настройка |
| --- | --- |
| OWNER_PASSWORD_HASH | Обязательный scrypt-хеш из интерактивной утилиты; только во внешнем env/config, не исходный пароль |
| APP_ORIGIN | Обязательный точный origin без завершающего `/`: локально `http://127.0.0.1:8000`; production `https://выбранный-домен` |
| NODE_ENV | Локально `development` (также default при отсутствии); production обязательно `production`, включает Secure cookie и требование HTTPS origin |

Для локального режима разрешены только http origins localhost/127.0.0.1. Production не стартует с HTTP origin или без корректного хеша. Прежние `PORT`, `COLLECTION_SPREADSHEET_ID`, `COLLECTION_SHEET_NAME`, `WISHLIST_SPREADSHEET_ID`, `WISHLIST_SHEET_NAME`, `GOOGLE_APPLICATION_CREDENTIALS` сохраняются; для acceptance нужны обе таблицы. Credentials остаются вне Git.

Пример локальной настройки (заменить внешний путь; каталог заранее должен существовать):

```bash
node scripts/hash-owner-password.mjs /absolute/path/outside-repository/owner-auth.env
node --env-file=.env --env-file=/absolute/path/outside-repository/owner-auth.env server/index.mjs
```

Утилита дважды запрашивает пароль без отображения; используйте уникальную фразу минимум 16 символов или пароль из менеджера. Не передавайте пароль аргументом команды/environment. Файл создаётся вне репозитория с правами 0600 и не перезаписывается, содержит только OWNER_PASSWORD_HASH. Сам хеш также следует защищать и не присылать в чат. Локальный `.env` содержит APP_ORIGIN/NODE_ENV и прежние настройки Sheets. `npm start` читает `.env`, если он есть, и поддерживает уже переданный environment. Не выполняйте `source` для произвольных env-файлов.

## Лимиты и будущий nginx

Фиксированные окна в памяти одного процесса:

- Login: 5 попыток на адрес подключения за 15 минут, 30 суммарно за окно. Успешные попытки тоже учитываются.
- Guest GET `/api/*`, включая session: 60 на адрес подключения за минуту, 300 суммарно. Статика не учитывается; owner GET не ограничивается этим лимитом.
- Превышение отклоняется до чтения Sheets/проверки пароля. Перезапуск сбрасывает лимиты. Redis и кэш данных не используются.

Адрес берётся только из TCP socket. X-Forwarded-For/X-Real-IP не считаются доверенными: их подмена не обходит лимиты. За nginx все посетители пока разделяют лимит loopback-адреса. Это консервативное ограничение минимальной версии; перед публикацией следует оценить его удобство. Изменение доверия к proxy и отдельные лимиты на посетителя требуют согласования вместе с deployment. Массовые запросы способны временно исчерпать общий лимит; это не DDoS-защита.

Будущая схема: Internet → существующий nginx → Node 127.0.0.1:8000 → Sheets. Nginx должен сохранять публичный Host, завершать TLS и не кэшировать API. Приложение не принимает forwarded-заголовок за доказательство HTTPS. Единственный процесс Node обязателен для текущей очереди записи. Порт 8000 наружу не открывается. WireGuard, NAT, firewall, SSH и Zabbix вне задачи. Caddy, Docker и дополнительные сервисы не нужны. До отдельного согласования эти требования не применяются на VPS.

## Acceptance локально

1. Запустить приложение с внешним хешем и текущими Sheets-настройками. Открыть точный APP_ORIGIN. При открытии обеих страниц в Network есть только auth/session, без GET записей. «Найти» и «Показать…» загружают актуальные записи. «Очистить» сбрасывает критерии и результаты без GET, устаревшие ответы игнорируются. Видно note, нет действий и storeUrl/покупок. В Network у GET нет UUID/приватных полей.
2. Проверить неверный пароль, затем войти. Видны действия owner и полные GET-модели. Пароль очищается из формы; основной экран остаётся прежним.
3. На заранее согласованных тестовых записях проверить добавление, отмену, удаление в обоих разделах, перенос и сохранность исходных данных. Реальные записи автоматически не создавались. Не проводить destructive acceptance на обычных записях.
4. Выйти: диалоги закрыты, действия и приватные данные исчезают. Старый cookie больше не даёт прав. При потере связи UI не утверждает, что выход состоялся.
5. Перезапустить приложение: требуется новый вход. Ошибки истечения сессии не повторяют запись. Конфликты, timeout и partial transfer проверять автоматически с подменённым источником, не повреждая реальные Sheets.
6. Выполнить `npm test` (Node 24) и `git diff --check`. Security tests проверяют прямые HTTP-запросы, cookie/CSRF, подделки, idle/absolute expiry, logout/restart, фильтрацию, rate limits и production cookie. Регрессии проверяют реальные бизнес-сервисы с memory repository после настоящего login.

Локальная проверка не подтверждает production TLS, DNS или nginx: они ещё не развёрнуты. Публикация возможна только отдельным согласованным шагом после acceptance.

## Результат проверки программного среза

Полный suite после UX-уточнений: 164/164 tests passed на Node 24.19.0 командой `node --test tests/*.test.mjs` (точная команда из npm test). `git diff --check` пройден. Self-review включал серверные guards, явный allowlist публичных полей, очистку приватного состояния и гонки auth/GET/logout; найденные ошибки исправлены и покрыты regression tests.

Интерактивная утилита хеша отдельно проверена на одноразовом тестовом пароле: ввод не отображается, файл имеет mode 0600, Node --env-file читает хеш и проверка пароля проходит. Временный файл удалён. Временный сервер с memory repositories остановлен.

Автоматическая визуальная browser-проверка не выполнена: инструмент не смог проверить административную политику доступа к localhost и заблокировал открытие preview. Ограничение не обходилось. UI handlers проверены автоматическим DOM harness; локальная acceptance authentication и UX подтверждена владельцем. Во время подготовки локального запуска выполнялась только GET-проверка реальных Sheets, автоматические записи не выполнялись. VPS не затрагивался.

## UX входа после локальной acceptance

Шапка обеих страниц: Vinyl Collection AI, постоянный подзаголовок «Музыка в лучшем формате», ниже подзаголовка единая строка: «Коллекция / Wish-list» слева, второстепенное «Войти» или «Выйти» справа. На узком экране строка может переноситься. Постоянных индикаторов роли нет; область статуса используется только для ошибок входа/выхода. Модальное окно «Вход» содержит поле «Пароль», secondary «Отмена» слева и основное «Войти» справа. Термины guest/owner остаются только в технической модели и документации. Серверные API, сессии, CSRF, лимиты и правила доступа этой UX-правкой не изменены.

Сценарий повторной UX-проверки (acceptance подтверждена): обновить обе страницы, проверить шапку и окно входа на desktop и узком окне (320–375 px), затем войти и выйти. Действие справа меняется в том же месте, управляющие кнопки появляются/исчезают, поиск и просмотр продолжают работать. Запись в Sheets для этой проверки не нужна.

Первоначальное открытие, переключение разделов, проверка сессии и login/logout не инициируют GET записей. После смены доступа результаты сбрасываются. GET списка выполняется по «Найти» / «Показать…», а также для существующих необходимых проверок и перечитываний при изменениях owner. Отложенная загрузка не является server-side filtering или pagination.

При финальном review исправлена локальная гонка: проверка неизменившейся сессии при возврате фокуса больше не отменяет незавершённое чтение данных для формы. Счётчик проверок сессии отделён от версии состояния доступа; logout и смена доступа по-прежнему отменяют устаревшие чтения. Добавлен regression test.
