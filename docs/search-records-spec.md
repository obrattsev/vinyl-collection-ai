Операция «Поиск пластинок в коллекции или получение всей коллекции»

Цель

Найти таблицу музыкальной коллекции, определить режим — получение всей коллекции либо поиск по критериям пользователя. Для поиска при необходимости уточнить или нормализовать критерии. Выполнить операцию без изменения данных и вернуть результат в табличной форме.

Поиск может использоваться как для одной конкретной пластинки, так и для выборки нескольких записей по одному или нескольким полям.

Контекст

- Коллекция хранится в Google Sheets.
- Одна строка основной коллекции соответствует одному приобретённому физическому экземпляру издания целиком.
- Двойной/многодисковый альбом и box set учитываются одной строкой, а не отдельной строкой на каждый диск.
- Одно и то же музыкальное произведение может присутствовать в коллекции в нескольких физических изданиях.
- Коллекцией управляет один пользователь.
- AI является основным интерфейсом чтения коллекции.
- Поиск и получение всей коллекции не изменяют данные.
- При необходимости проверки написания исполнителя, альбома, лейбла, года выпуска или определения информации по фотографии разрешается использовать интернет.
- Интернет используется только как дополнительный источник для уточнения поисковых критериев, а не как замена данным коллекции.

Поиск может выполняться по любому полю или комбинации полей:

1. Исполнитель.
2. Альбом.
3. Жанр.
4. Лейбл.
5. Год альбома.
6. Год пластинки.
7. Тип издания.
8. Дата покупки.
9. Магазин покупки.
10. Цена покупки.
11. Примечание.

Пользователь также может предоставить фотографию пластинки. В этом случае AI пытается определить доступные признаки и использует их как критерии поиска.

Box set и многодисковые комплекты

- Одна строка соответствует физическому изданию/комплекту целиком; отдельные диски внутри комплекта отдельными строками не создаются.
- Для box set поле «Альбом» содержит официальное название самого box set.
- Поле «Исполнитель» содержит основного исполнителя комплекта. Если комплект содержит записи разных исполнителей и не имеет одного основного исполнителя, использовать «Various Artists».
- «Год альбома» означает год первоначального выпуска самого box set/релиза как самостоятельного издания, а не годы отдельных включённых в него альбомов.

Форматы данных

- Год альбома и год пластинки: "YYYY".
- Поле «Тип издания» может принимать значения «Оригинал», «Переиздание» или оставаться пустым.
- Пустое значение поля «Тип издания» означает, что тип издания неизвестен.

- «Оригинал» — физическое издание, относящееся к первоначальному выпуску альбома и не обозначенное как переиздание/reissue/repress/remaster.
- «Переиздание» — последующий выпуск ранее изданного альбома, включая явно обозначенные reissue/repress/remaster.
- Если тип издания нельзя определить достоверно, поле остаётся пустым.
- Совпадение года альбома и года пластинки само по себе недостаточно для определения «Оригинал».
- Дата покупки хранится в формате "YYYY-MM-DD": либо полная дата, либо пустое поле. Неполная дата не хранится.
- Цена покупки хранится числом в рублях; отдельное поле валюты в MVP не используется.
- Пустая цена означает, что цена неизвестна; 0 означает, что пластинка получена бесплатно.

Нормализация написаний перед сравнением

- При сравнении текстовых значений игнорировать регистр, начальные и конечные пробелы; последовательности нескольких пробелов считать одним пробелом.
- Пунктуацию, дефисы, апострофы и сами слова автоматически не нормализовать.
- Предполагаемые опечатки и альтернативные написания показывать пользователю и исправлять только после подтверждения.
- Нормализацию выполнять до поиска дублей и любого сравнения значений. Эти правила относятся к сравнению, а не к автоматическому исправлению данных таблицы.

Правила и ограничения

1. Поиск и получение всей коллекции являются только операциями чтения.
2. Во время поиска и получения всей коллекции запрещено добавлять, изменять, удалять или перезаписывать строки.
3. Поиск может выполняться:
   - по одному полю;
   - по комбинации нескольких полей;
   - по точному значению;
   - по частичному совпадению для текстовых полей, если пользователь явно это допускает или ввод не является полным: искать подстроку без учёта регистра после нормализации;
   - если передано полное существующее значение, использовать точное совпадение после нормализации.
   Для года альбома, года пластинки, типа издания, даты и цены в MVP поддерживается только точное совпадение (для полей, присутствующих в соответствующем списке). Диапазоны годов, дат и цен в MVP не поддерживаются.
4. Проверять написание исполнителя, альбома и лейбла.
5. Контролировать консистентность поисковых значений с уже существующими значениями таблицы.
6. Если пользователь указал значение, похожее на существующее, но написанное иначе, показать найденный вариант и использовать исправленное значение только после подтверждения пользователя.
7. Если пользователь сформулировал однозначные критерии поиска, отдельное подтверждение перед выполнением поиска не требуется.
8. Если критерии неоднозначны или были автоматически определены по фотографии, показать пользователю проект поискового запроса и запросить подтверждение либо корректировку.
9. Допускать прямые команды без предварительного входа; команда "Начинаем работу с Коллекцией" также открывает общий режим работы.
10. Завершать режим работы после команды "Завершаем работу с Коллекцией", отменяя текущую незавершённую операцию согласно разделу «Отмена незавершённой операции».

Получение всей коллекции без критериев

Запрос «Покажи коллекцию» или однозначный эквивалент без критериев означает получение всей основной коллекции. Дополнительное подтверждение не требуется.

Вход в пользовательские сценарии

- Прямые пользовательские команды разрешены; предварительная команда «Начинаем работу с Коллекцией» не обязательна.
- Команда «Начинаем работу с Коллекцией» остаётся допустимым способом войти в общий режим работы.
- Если пользователь говорит «Добавить пластинку» или эквивалент и не указывает wish-list, целевой таблицей считается основная коллекция.
- Для добавления в wish-list пользователь должен явно указать wish-list.
- Если намерение или целевая таблица всё же неоднозначны, AI должен запросить уточнение, а не угадывать.

Отмена незавершённой операции

- Пользователь может отменить текущую незавершённую операцию командой «Отмена» или однозначным эквивалентом.
- «Завершаем работу с Коллекцией» также отменяет текущую незавершённую операцию, если такая существует.
- При отмене текущий неподтверждённый проект записи или поискового запроса отбрасывается.
- Отменённый проект не записывается в Google Sheets и не сохраняется для автоматического продолжения позже.
- После отмены пользователь может начать новую операцию.

Алгоритм

Старт

По прямому запросу или после команды "Начинаем работу с Коллекцией" определить действие пользователя и целевую таблицу согласно разделу «Вход в пользовательские сценарии».

Если пользователь запросил всю коллекцию без критериев, перейти к получению всей основной коллекции. Если пользователь хочет выполнить поиск по критериям, предложить способ:

- по фотографии;
- вручную.

Получение всей основной коллекции

1. Найти Google Sheets-документ основной коллекции.
2. Прочитать все существующие строки без изменения данных и без дополнительного подтверждения.
3. Если записей нет, вернуть «Коллекция пуста».
4. Если записи есть, вернуть все строки в табличной форме с набором полей по умолчанию из раздела «Формат результата».

Поиск по фотографии

1. Проанализировать фотографию.
2. Определить поля, которые можно достоверно распознать.
3. Отделить достоверные значения от предположений.
4. При необходимости использовать интернет для проверки распознанной информации.
5. Показать пользователю найденные значения и предположения.
6. При необходимости запросить дополнительные критерии поиска.
7. Проверить написание исполнителя, альбома и лейбла.
8. Нормализовать текстовые значения и сопоставить их с существующими значениями таблицы.
9. Сформировать проект поискового запроса.
10. Показать проект пользователю.
11. Запросить подтверждение либо корректировку.
12. После подтверждения выполнить поиск.

Ручной поиск

1. Получить от пользователя один или несколько критериев поиска.
2. Определить, по каким полям необходимо искать.
3. При необходимости уточнить дополнительные критерии.
4. Проверить написание исполнителя, альбома и лейбла.
5. Нормализовать текстовые значения и сопоставить их с существующими значениями таблицы.
6. Выбрать ровно одну ветку:
   - Если критерии однозначны — выполнить поиск один раз без дополнительного подтверждения и вернуть результат.
   - Если критерии неоднозначны — сформировать проект поискового запроса, показать пользователю и запросить подтверждение либо корректировку. После согласования выполнить поиск один раз и вернуть результат.
7. Завершить ручной поиск; повторно выполнять тот же поиск в рамках этого алгоритма не требуется.

Поиск

При выполнении поиска:

1. Проверить форматы переданных значений.
2. Не изменять данные таблицы.
3. Применить все заданные критерии одновременно.
4. Вернуть все записи, соответствующие условиям.
5. Если совпадений нет — вернуть сообщение:
   "По поисковому запросу пластинок не найдено".

Формат результата

Результаты поиска и всю основную коллекцию возвращать в табличной форме.

По умолчанию показывать:

Исполнитель| Альбом| Жанр| Лейбл| Год альбома| Год пластинки| Тип издания

Если пользователь искал по полям покупки или примечанию, дополнительно показать релевантные поля:

- Дата покупки;
- Магазин покупки;
- Цена покупки;
- Примечание.

Если найдено несколько физических изданий одного альбома, показать каждое отдельной строкой.

Результат

Один из вариантов:

- вся основная коллекция в табличной форме;
- сообщение «Коллекция пуста» при запросе всей пустой коллекции;
- таблица с пластинкой или пластинками из коллекции, соответствующими поисковому запросу;
- сообщение "По поисковому запросу пластинок не найдено".

Проверка результата

После выполнения операции AI должен убедиться, что:

- при получении всей коллекции возвращены все существующие строки;
- при поиске применены именно согласованные критерии поиска;
- форматы данных интерпретированы корректно;
- результат содержит только подходящие записи;
- все подходящие записи включены в результат;
- данные коллекции не были изменены.

Критерии успеха

Операция считается успешной, если:

- выполнено получение всей коллекции либо поиск по корректным критериям;
- пользователь получил все строки коллекции либо все подходящие записи поиска;
- при пустой коллекции или отсутствии совпадений пользователь получил соответствующее сообщение;
- существующие данные коллекции не были изменены.
