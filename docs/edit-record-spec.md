# Редактирование записи коллекции и wish-list — 3A

Статус: реализовано, автоматические проверки и независимый финальный review пройдены. Локальная acceptance всего 3A успешно завершена и принята владельцем.
Связанные документы: [правила данных](data-rules.md), [backlog](backlog.md), [локальная приёмка](stage-3a-acceptance.md).

## Сценарий owner

1. «Редактировать» открывает все пользовательские поля выбранной записи: 12 у Collection, 10 у Wish-list. UUID неизменяем и не является полем формы.
2. Предзаполнение сохраняет null, цену 0 и жанр вне справочника: существующее значение можно оставить или заменить. Неизменённые поля сохраняют исходное значение даже при нормализации переносов строк нативным input или более точной сохранённой цене; preview показывает полный сохранённый текст. Выбор новых жанров — из общего справочника. Дата покупки показывается/вводится DD-MM-YYYY, перед API преобразуется в YYYY-MM-DD без timezone parsing.
3. «Проверить и просмотреть» повторно читает актуальные данные, проверяет версию, прежнюю валидацию и дубли. Собственный UUID исключается только из целевого списка; Wish-list также проверяется против Collection. Подтверждённый дубль блокируется; неполные признаки дают предупреждение и допускают подтверждение. Никакой смысловой нормализации не добавлено.
4. Preview показывает все пользовательские поля и выделяет изменённые значения с подписью «Было → Стало». «Исправить» требует повторного preview. Только «Подтвердить изменения» выполняет PUT. Отмена отбрасывает ввод без записи.
5. После подтверждённого успеха повторяется последний выполненный поиск с активной сортировкой. Запись, переставшая соответствовать поиску, исчезает из результата.

## API

`PUT /api/collection/:id`, `PUT /api/wishlist/:id` принимают полный набор пользовательских полей без id. Все необязательные пустые значения — null; отсутствующие/лишние поля, id в body и недопустимые значения отклоняются. Content-Type: application/json. Обязательный If-Match — существующая quoted SHA-256 ревизия полного исходного record (все 13/11 полей), без новой колонки version. PATCH не поддерживается.

Операция требует owner-сессию, корректный Host/Origin и CSRF. Проверки выполняются до бизнес-чтения/записи. Guest не получает новые поля или права.

- 200 — фактически проверенная полная запись с прежним UUID.
- 400 INVALID_REQUEST — неправильный UUID/If-Match/JSON; INVALID_RECORD — неправильный проект.
- 404 NOT_FOUND — запись исчезла; черновик не создаёт замену автоматически.
- 409 RECORD_CHANGED с актуальной record — версия изменилась, запись не производится.
- 409 POTENTIAL_DUPLICATE с records — подтверждённый дубль издания.
- 500 RESULT_UNCONFIRMED с id — фактический результат записи не удалось подтвердить.

Ошибки чтения, целостности и доступа сохраняют существующий контракт соответствующего списка.

## Конфликт и неопределённость

При RECORD_CHANGED введённые значения остаются в форме. Актуальная запись показывается отдельно; подтверждение блокируется. Пользователь нажимает «Пересмотреть изменения относительно актуальной записи», вручную пересматривает поля и заново получает полный preview. Новая ревизия применяется только после этого явного действия. Автоматического merge, повторного PUT или перезаписи нет. Повторный конфликт снова требует пересмотра. Отмена закрывает форму.

При RESULT_UNCONFIRMED нет автоматического повтора. Изменения блокируются до нового успешного чтения; устаревший GET не снимает блокировку. Потерянный ответ сам по себе не означает неуспех: сервер проверяет фактическое состояние перечитыванием. При исчезновении записи автоматическое добавление или восстановление не выполняется.

## Хранилище и ограничения

Редактирование использует ту же очередь одного процесса, что добавление, удаление и перенос. Сервис читает запись по UUID и сравнивает ревизию. Адаптер повторно читает и валидирует документ, находит актуальную физическую строку по UUID и повторяет проверку непосредственно перед записью.

Один Sheets batchUpdate изменяет только известные пользовательские ячейки через типизированные stringValue/numberValue; null очищает значение. UUID, неизвестные колонки, формулы неизвестных колонок и форматирование сохраняются. Пользовательский текст не интерпретируется как формула. Порядок заголовков произвольный, строки не переставляются.

После попытки записи сервис перечитывает список, сверяет всю целевую запись и неизменность остальных записей. Повторной записи после timeout нет. Модели, заголовки Sheets и права Google не меняются, миграция не нужна.

Sheets не предоставляет транзакционный CAS между чтением и записью. Ручные конкурентные изменения Sheets и несколько серверов записи остаются неподдерживаемыми; запоздалое применение запроса Google после timeout возможно. История, аудит, массовые операции и новые механизмы хранения не входят в 3A.
