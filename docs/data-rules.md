# Общие правила данных

Статус: согласовано. Этап: 1. Связанные документы: [README](../README.md), [backlog](backlog.md).

## Хранение и поля

На этапе 1 используются два отдельных реальных документа Google Sheets: коллекция и wish-list. Один владелец. В коллекции одна строка — один приобретённый физический экземпляр издания целиком; в wish-list — одна желаемая пластинка или конкретное желаемое издание. Многодисковые комплекты и box set не разбиваются на диски.

Общие поля: Исполнитель (обязательно), Альбом (обязательно), Жанр, Дополнительный жанр, Лейбл, Год альбома (обязательно), Год пластинки, Тип издания, Примечание.

Только коллекция: Дата покупки, Магазин покупки, Цена покупки. Только wish-list: Ссылка на онлайн-магазин.

Состав модели данных не ограничивается критериями ручного поиска. На этапе 1 [ручной поиск основной коллекции](search-records-spec.md) использует только Исполнитель, Альбом, Год альбома и единый критерий Жанр, проверяющий оба жанровых поля. Остальные поля сохраняются в модели; отдельного критерия Дополнительный жанр в этом интерфейсе нет.

Для box set: Альбом — официальное название комплекта; Исполнитель — основной исполнитель либо Various Artists при отсутствии единственного основного исполнителя; Год альбома — первый выпуск комплекта как самостоятельного релиза.

## Форматы

- Годы: YYYY.
- Тип издания: Оригинал, Переиздание либо пусто (неизвестно).
- Оригинал — физическое издание первоначального выпуска, не обозначенное reissue/repress/remaster. Переиздание — последующий выпуск, включая reissue/repress/remaster. Совпадение годов не определяет тип автоматически; при неизвестном типе поле пустое.
- Дата покупки: полная календарная дата YYYY-MM-DD либо пусто. Неполная дата не хранится.
- Цена: число в рублях. Пусто — неизвестно, 0 — бесплатно. Отдельного поля валюты нет.
- Ссылка на магазин: корректный URL либо пусто.
- Дополнительный жанр необязателен; заполненное значение отличается от основного жанра после нормализации. Поиск по жанру проверяет оба поля (достаточно совпадения одного).

## Сравнение и консистентность

При сравнении игнорировать регистр и крайние пробелы, последовательности пробелов считать одним. Не изменять пунктуацию, дефисы, апострофы, слова или транслитерацию. Нормализация выполняется до любого сравнения; сохранённые значения автоматически не исправляются.

Предлагать существующие значения исполнителей, альбомов и лейблов; применение подсказки выбирает пользователь. Для коллекции учитывать коллекцию, для wish-list — оба документа. На этапе 1 автоматически нормализуются только технические различия, перечисленные выше. Смысловое исправление опечаток, сопоставление альтернативных написаний и другие AI-подобные проверки, включая проверку фактического существования релиза, не выполняются. Разные написания могут скрывать дубли — это явное ограничение; пользователь отвечает за введённые сведения. Семантические проверки перенесены в [этап 3](ai-stage.md).

## Потенциальные дубли при добавлении

Сначала сравнить Исполнитель + Альбом. При совпадении сравнить максимально доступные Лейбл + Год пластинки + Тип издания. Различие признака, заполненного в обеих записях, означает разные издания. Если различие не установлено, это потенциальный дубль: блокировать добавление и показать найденные записи для уточнения. Одного подтверждения недостаточно для обхода блокировки.

Для коллекции проверять существующие записи коллекции. Для wish-list проверять wish-list и коллекцию: совпадение альбома в коллекции требует предупреждения, а потенциальное совпадение издания блокирует добавление. Другой выпуск того же альбома допустим.

## Подтверждение и отмена

Перед записью показать полный проект строки; исправления требуют просмотра и подтверждения обновлённого проекта. Перед редактированием и удалением также необходимо подтверждение. Подробности редактирования ещё согласуются; удаление выполняется по [согласованному сценарию](delete-record-spec.md), с сообщением об успехе только после проверки результата. Кнопка «Отмена» отбрасывает текущий неподтверждённый проект без записи и автоматического продолжения позже.

Для ручного поиска основной коллекции вместо отдельной операции «Отмена» используется очистка формы по [спецификации поиска](search-records-spec.md): очищаются четыре критерия и общий режим без нового поиска и изменения данных. Правила отмены остальных операций сохраняются.

## Вопросы до реализации интеграции

Формат/хранение устойчивого идентификатора, проверка колонок, поведение при изменении данных извне, тайм-ауте и неопределённом результате записи требуют отдельной спецификации (backlog 8–12). Приложение не должно сообщать успех без проверки результата.
