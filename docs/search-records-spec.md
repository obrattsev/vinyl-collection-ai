# Просмотр и поиск в коллекции

Статус: реализовано для интерфейса без AI в завершённом локальном MVP. Этап: 1.
Связанные документы: [правила данных](data-rules.md), [будущий AI](ai-stage.md).

## Поведение

Получение всего списка возвращает все строки без подтверждения. Поиск и просмотр ничего не изменяют ни в одном документе. При интеграции UI получает коллекцию через `GET /api/collection` собственного API во внутренней модели. API обращается к отдельному Google Sheets-документу основной коллекции через слой доступа к данным; прямого обращения браузера к Sheets нет. Текущий UI использует этот GET; локальный тестовый JSON не является источником или fallback.

Ручной интерфейс содержит только четыре критерия: Исполнитель, Альбом, Год альбома и Жанр. Их можно использовать отдельно или одновременно. Выбора режима текстового поиска в UI нет. Год альбома ищется только по точному совпадению в формате YYYY.

Текст сравнивается автоматически после общей нормализации: подходит как полное совпадение значения, так и вхождение введённого текста в значение. При одновременном наличии точных и частичных совпадений показываются все подходящие записи без ранжирования и без скрытия частичных совпадений. Запись должна соответствовать всем заполненным критериям (И). Один критерий Жанр проверяется одновременно по полям Жанр и Дополнительный жанр по тем же правилам; достаточно совпадения любого из них (ИЛИ). Отдельного пользовательского критерия Дополнительный жанр нет. Диапазоны не поддерживаются.

Поиск по остальным полям основной коллекции не реализуется в ручном интерфейсе этапа 1. Ограничение относится только к критериям интерфейса и не удаляет поля из модели данных.

Пустой критерий (в том числе текст, пустой после общей нормализации) означает, что фильтр по соответствующему полю не применяется. Он не означает поиск записей с пустым полем. Если непустых критериев нет, возвращается весь список.

Сначала проверить форматы непустых критериев. При корректных критериях выполнить поиск без дополнительного подтверждения. Применять только техническую нормализацию по общим правилам данных; смысловое исправление написаний и AI-подобные проверки относятся к этапу 4.

Кнопка «Очистить» очищает все четыре критерия и возвращает результаты в начальное состояние «Здесь появятся результаты поиска.». Запоздалые ответы предыдущих запросов игнорируются. Она не выполняет новый поиск и не изменяет данные коллекции. Отдельная бизнес-операция «Отмена» для незавершённого ручного поиска основной коллекции не используется.

Поле «Год альбома» сохраняет placeholder «Например, 1979»: набор и вставка допускают только до четырёх ASCII-цифр; `inputmode="numeric"` предлагает цифровую клавиатуру. Ограничение ввода не заменяет проверку полного YYYY перед поиском. Жанр выбирается из единого `src/genres.mjs`, как при добавлении; «Любой жанр» отключает фильтр. Сопоставление по обоим жанровым полям сохраняется. Эти controls и структура карточки общие с wish-list.

## Результат

Все подходящие строки, каждое физическое издание отдельно, в таблице:

Исполнитель | Альбом | Жанр | Дополнительный жанр | Лейбл | Год альбома | Год пластинки | Тип издания

Пустой полный список: «Коллекция пуста».
Нет совпадений поиска: «По поисковому запросу пластинок не найдено».

`GET /api/collection` возвращает `200 OK` и JSON-массив `CollectionRecord` по общему mapping (либо `[]`). GET не создаёт и не исправляет ID. Нарушение целостности ID или отсутствие обязательного значения приводит к явной ошибке с полем `error`, а не к пустой коллекции или автоматическому исправлению.

Технический UUID сохраняется в модели полученных записей, но не обязан отображаться в обычной таблице. Он не добавляет новый пользовательский критерий поиска; состав восьми отображаемых полей выше сохраняется.

## Приёмка

Возвращены все и только соответствующие записи, применены все выбранные критерии, форматы интерпретированы корректно. Исходные данные не изменились. Пустой список отличается от отсутствия совпадений; ошибка чтения не отображается как пустой список.

Гибкий поиск естественным языком, более сложные запросы по данным коллекции и поиск по фотографии — AI-интерфейс этапа 4. Подробности расширенного поиска требуют спецификации; см. [AI-этап](ai-stage.md) и [backlog](backlog.md).

При открытии раздела данные не загружаются. «Найти» получает актуальный полный набор и применяет прежний клиентский поиск; «Показать коллекцию» получает и показывает весь набор. Переход между разделами сам по себе не вызывает GET записей. Перечитывания после изменений и блокировки при неподтверждённом результате сохраняются; очистка не снимает эти блокировки.
