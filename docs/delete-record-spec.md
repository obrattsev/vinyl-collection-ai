# Удаление записи коллекции и wish-list

Статус: простой пользовательский сценарий согласован; детали интеграции требуют спецификации перед реализацией. Этап: 1.
Связанные документы: [правила данных](data-rules.md), [backlog](backlog.md).

## Сценарий

Операция входит в локальный MVP обеих таблиц и выполняется через веб-интерфейс без AI.

1. Пользователь выбирает запись в основной коллекции или wish-list.
2. Приложение показывает подтверждение удаления выбранной записи.
3. Пользователь подтверждает удаление. До подтверждения данные не изменяются; при отмене запись сохраняется.
4. Приложение удаляет выбранную запись из соответствующего Google Sheets-документа.
5. Приложение проверяет результат удаления.
6. Только после успешной проверки сообщает об успешном удалении.

Посторонние записи не должны изменяться. Ошибка или неопределённый результат удаления не выдаются за успех. Undo не входит в текущий MVP; идея сохранена как будущее UX-улучшение в [backlog, пункт 21](backlog.md#21-undo-после-удаления).

Для основной коллекции используется `DELETE /api/collection/:id` через собственный API и слой доступа к данным. В обеих коллекциях запись идентифицируется по постоянному UUID из [правил данных](data-rules.md#постоянный-id-записей), не по номеру строки Sheets. Удаление не перенумеровывает оставшиеся записи; удалённый ID не переиспользуется. Успешный ответ — `200 OK` и фактически удалённый `CollectionRecord` в JSON. Если запись не найдена — `404`. Базовые ошибки и общий JSON-формат с полем `error` определены в [контракте API](../README.md#архитектура-доступа-к-данным-и-api). Маршруты API wish-list здесь не определяются; модель записи — `WishlistRecord` по общим правилам данных.

## Вопросы перед реализацией интеграции

- Что делать, если выбранная запись изменилась после открытия подтверждения? Поведение исчезнувшей записи основной коллекции определено ответом `404`; для wish-list оно ещё требует согласования.
- Как технически проверять результат, обрабатывать сбой и повторную попытку?

Эти детали должны быть зафиксированы до реализации интеграции. Сценарий не утверждает массовые операции, архивирование, историю или новый способ хранения.
