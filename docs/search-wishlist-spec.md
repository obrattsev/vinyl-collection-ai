# Просмотр и поиск в wish-list

Статус: реализовано для интерфейса без AI; покрыто автоматическими тестами. Этап: 1.
Связанные документы: [правила данных](data-rules.md), [поиск коллекции](search-records-spec.md), [перенос](add-wishlist-record-spec.md#перенос-wish-list--collection).

## Поведение

Wish-list и основная коллекция используют одинаковую структуру карточки поиска, расположение, подписи и подсказки четырёх полей: Исполнитель, Альбом, Год альбома и Жанр. Выбора режима сопоставления нет. Остальные поля WishlistRecord не являются критериями ручного поиска.

Текст под заголовком: «Найдите нужные пластинки в своем wish-list. Оставьте поля пустыми, чтобы не учитывать их при поиске.»

UI читает `GET /api/wishlist` через собственный API и слой доступа к отдельному Google Sheets-документу. Поиск выполняется общей для обоих разделов функцией; `searchWishlist` использует тот же контракт, что `searchCollection`. Поиск ничего не записывает. Локальный JSON не является источником или fallback.

Исполнитель и Альбом автоматически сопоставляются как полное совпадение или подстрока после нормализации регистра и пробелов по правилам данных. Все подходящие строки отбираются без ранжирования совпадений, затем применяется общая сортировка 3A. Заполненные критерии объединяются через AND. Год альбома — точное совпадение YYYY. Критерий Жанр проверяет основной и дополнительный жанр; достаточно совпадения любого поля. Правило текстового сопоставления жанра сохраняется общим с коллекцией.

Год допускает только до четырёх ASCII-цифр при наборе, вставке и input-событиях; `inputmode="numeric"` предлагает цифровую клавиатуру. Подпись «Год альбома» и placeholder «Например, 1979» сохранены. Неполный непустой год отклоняется бизнес-валидацией до чтения данных. Жанр выбирается из единого `src/genres.mjs`, как при добавлении; пустой пункт «Любой жанр» отключает фильтр. Отдельного справочника нет.

Пустые критерии не ограничивают поиск, пустая форма возвращает весь wish-list. «Показать весь wish-list» игнорирует критерии формы. «Очистить» сбрасывает четыре значения и ошибку критериев без нового запроса или изменения данных; область результатов возвращается к «Здесь появятся результаты поиска.», запоздалые ответы игнорируются.

## Результат

Все подходящие строки, каждое физическое издание отдельно, в таблице:

Исполнитель | Альбом | Жанр | Дополнительный жанр | Лейбл | Год альбома | Год пластинки | Тип издания | Примечание | Ссылка

Пустой полный список: «Wish-list пуст».
Нет совпадений: «По поисковому запросу записей в wish-list не найдено».
Ошибка источника или целостности не отображается как пустой список. Ненастроенный источник сообщает `WISHLIST_NOT_CONFIGURED`.

UUID входит только в полную owner-модель и не отображается/не экспортируется. Guest получает девять публичных полей без UUID и Ссылки. GET ничего не исправляет. Все применимые ключи присутствуют, необязательные пустые значения — `null`.

Действия owner-строки «Добавить в коллекцию», «Редактировать» и «Удалить» имеют одинаковую высоту и постоянный промежуток. После переноса приложение автоматически перечитывает необходимые данные. При полном успехе исходник исчезает из wish-list; при частичном сохраняется отдельное сообщение о подтверждённой записи в коллекции и незавершённом удалении. Устаревший GET не может перезаписать новое состояние. Отдельной ручной синхронизации нет.

## Приёмка

Проверить четыре критерия по отдельности и вместе, автоматический поиск подстроки, AND, оба жанра, пустой поиск и очистку без запроса. Проверить общий справочник и ограничение года на обеих вкладках. Различать пустой список, отсутствие совпадений и ошибку чтения. Проверить полный и частичный перенос, автоматическое обновление и защиту от устаревших ответов. Исходные данные поиск не изменяет.

Поиск по фотографии и свободные команды относятся к этапу 4.

При открытии wish-list (в том числе переходом из Collection) GET записей не выполняется. Только «Найти» и «Показать весь wish-list» запрашивают актуальные данные для просмотра; поиск по-прежнему клиентский. Перечитывания после изменений сохраняются; «Очистить» не снимает блокировки восстановления после неподтверждённых операций.

Сортировка, сохранение её состояния и CSV полностью следуют [общему контракту 3A](search-records-spec.md#сортировка-и-скачивание-3a). Ссылка видна и экспортируется только owner.
