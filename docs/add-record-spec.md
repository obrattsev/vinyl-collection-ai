# Добавление в коллекцию

Статус: согласовано для интерфейса без AI. Этап: 1.
Связанные документы: [правила данных](data-rules.md), [будущий AI](ai-stage.md), [backlog](backlog.md).

## Сценарий

1. Пользователь открывает добавление в явно выбранном разделе «Коллекция». Целевой документ виден в форме и при подтверждении.
2. Вручную заполняет обязательные и выбранные необязательные поля из правил данных, включая дополнительный жанр. Существующие написания предлагаются как подсказки, не применяются автоматически.
3. Приложение проверяет обязательность и форматы, нормализует значения только для сравнения. Проверить потенциальные дубли в основной коллекции; при совпадении показать записи и заблокировать добавление до уточнения.
4. Показывает полный проект новой строки. Пользователь может исправить данные, отменить операцию или подтвердить проект. Исправленный проект проверяется и подтверждается заново.
5. После подтверждения повторно проверяет форматы и дубли по актуальным данным.
6. Добавляет ровно одну строку в конец целевого документа, не перезаписывая существующие строки.
7. Перечитывает добавленную строку и сравнивает с подтверждённым проектом. Сообщает успех только после проверки.

## Критерии приёмки

- Все общие поля и поля целевого документа доступны; обязательные поля заполнены, форматы соблюдены.
- Потенциальный дубль не добавляется даже после подтверждения; недостаток признаков требует уточнения.
- До подтверждения и после отмены запись не выполняется.
- Успешное добавление создаёт одну строку в конце, совпадающую с проектом; существующие данные обоих документов сохраняются.
- Ошибки и неопределённый результат записи не выдаются за успех; правила восстановления и повторных попыток должны быть согласованы по backlog 10–12 до подключения записи.

Фото, AI-команды и интернет-уточнение перенесены на этап 3. Перенос покупки из wish-list не является частью этой операции.
