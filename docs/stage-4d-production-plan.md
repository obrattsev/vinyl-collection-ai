## Rollback приложения

- До live DDL: прежний release остаётся выбранным. Проверить фазу; восстановить записанные worker/timer/freeze/ingress состояния после smoke. Не объявлять откат выполненным без проверки.
- После DDL/startup failure: ingress закрыт, statistical timers остановлены; определить schema 5/6/7. Read-only compatibility gate для exact предыдущего SHA и фактической schema обязателен. При совместимости остановить candidate, вернуть прежний feature env (не AUTH_SECRET и auth config), атомарно вернуть current на сохранённый previous и запустить app.
- **PostgreSQL не откатывать.** 006/007, новые reports/statistics и пользовательские данные сохраняются; dump не восстанавливать. Pending delivery ждёт совместимого кода, unknown не replay-ить. Старый binary на schema 7 проверен локально; live exact artifact проверяется снова.
- Проверить сессию/чтение/privacy/Covers, зеркало, backup, freeze и HTTPS до открытия ingress. Если предыдущий binary несовместим, оставить maintenance и согласовать forward fix; не делать автоматический DB restore.
- При rollback старый код не учитывает новые события статистики: timers держать выключенными, неполноту периода зафиксировать перед возобновлением. Disaster restore — отдельное разрешение и действующий quarantine/recovery, а не способ обычного rollback.
