## Контракт

- Wish-list owner: исходный HTTP(S) URL в desktop заменён видимым текстом «Открыть в магазине ↗», в mobile detail — «Открыть ↗». href сохраняет исходное значение, target=_blank, rel=noopener noreferrer. Ссылка ограничена по ширине, URL не становится видимым текстом. Guest по-прежнему не получает storeUrl.
- Существующая validStoreUrl использует URL parser и допускает другие схемы. Модель/валидация хранения не менялись. Presentation дополнительно допускает активные ссылки только с protocol http:/https:. Неразбираемые значения, javascript:/data:/ftp: не становятся активными ссылками, показываются обычным безопасным текстом. В edit полный исходный URL не сокращается.
- Desktop note отображается в блоке шириной до 16rem, nowrap/overflow hidden/text-overflow ellipsis. Ограничение не применяется к данным, mobile detail или CSV. В edit используется textarea для полного многострочного значения. Store cell ограничен 12rem, включая неактивный fallback.
- Owner Collection desktop и mobile detail показывают все 12 пользовательских полей, включая дату/магазин/цену покупки; дата DD.MM.YYYY, цена в рублях по существующему numeric/null контракту, 0 отображается как 0, null пусто. Guest получает только 9 публичных полей. UUID не показывается. Заголовки owner-only колонок скрываются при выходе, строки очищаются прежним механизмом.
- CSV сохраняет явно согласованный контракт 3A/3B: guest в обоих разделах — 9 колонок; owner Collection — 9 без полей покупки; owner Wish-list — 10, включая исходный URL. Для одной роли/displayedRecords desktop/mobile экспорт совпадает; поиск определяет набор, ручная сортировка порядок. Полные note/URL экспортируются с прежними CSV escaping/formula-injection защитой. Расширение owner desktop не расширяет CSV.
- Все th выровнены по вертикальному центру. Примечание, Ссылка, поля покупки и Действия не получили sortable controls. Существующие восемь sortable полей и activeSort не менялись.
- Текстовые action buttons и столбец Действия сохранены. Компактные icon actions добавлены только как идея «Без этапа» в backlog.

## Local acceptance

Использовать существующий изолированный стенд http://127.0.0.1:8013/collection и /wishlist; обновить страницу. Пароль `local-acceptance-only`. При необходимости запуск: `node scripts/local-acceptance.mjs` из репозитория с Node 24. Все данные в памяти, Google не используется.

1. Войти, открыть Wish-list и отредактировать вымышленную запись: добавить длинный HTTPS URL, например `https://example.com/?album=` с длинным текстом после `=`, и многострочное примечание. Сохранить. На desktop ссылка — «Открыть в магазине ↗», note ограничен с ellipsis, их длина не раздвигает столбцы. Нажатие открывает исходный URL в новой вкладке.
2. На ширине 390 px открыть detail: «Открыть ↗», полное note с переносами. Редактирование показывает полный URL и note, отмена ничего не меняет. Проверить длинное слово без пробелов в note. Для не-HTTP схемы (например mailto:test@example.com) нет активной ссылки; другие схемы/невалидный текст покрыты тестом защитного рендера.
3. Collection owner: на desktop видны Дата покупки / Магазин покупки / Цена покупки (руб.), те же значения в mobile detail. На стенде поставить цену 0, затем отдельно очистить — 0 и пустое значение различаются. Дата сохраняет DD.MM.YYYY. Выйти, заново показать список: приватных полей/заголовков нет.
4. Скачать CSV на desktop и mobile при одинаковых поиске и сортировке. Состав и порядок совпадают, полные note/URL сохранены. Owner Collection — 9 колонок без покупок, owner Wish-list — 10 с URL. Guest — 9 без private. Поиск Alpha и смена направления сортировки отражаются в экспорте.
5. На desktop проверить выравнивание Примечание/Ссылка/поля покупки/Действия относительно sortable заголовков. Они не стали кнопками. Текущие edit/delete/transfer actions сохранены.
