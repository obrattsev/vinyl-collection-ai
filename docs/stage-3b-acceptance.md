# Локальная acceptance 3B

Статус: реализация в feature/stage-3b, основная функциональность и повторная UX acceptance приняты владельцем. Production и реальные Sheets не изменялись. Автоматический браузер отказал в доступе к localhost из-за недоступной проверки административной политики; автоматическая визуальная проверка не выполнена. Владелец выполнил local acceptance и принял результат, включая UX-коррекцию.

## Запуск

```sh
cd /Users/obrattsev/vinyl-collection-ai
node scripts/local-acceptance.mjs
```

Если Node отсутствует в PATH этого Mac:

```sh
cd /Users/obrattsev/vinyl-collection-ai
/Users/obrattsev/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node scripts/local-acceptance.mjs
```

Открыть http://127.0.0.1:8013/collection и http://127.0.0.1:8013/wishlist. Тестовый пароль owner: `local-acceptance-only`. Стенд слушает loopback, не читает .env и не обращается к Google. Все коллекции и reports — вымышленные данные в памяти; перезапуск сбрасывает данные и лимиты. Закрыть старый экземпляр Ctrl+C, если порт занят. Для проверки узкой ширины используйте окно браузера/Device Toolbar на этом компьютере: адрес loopback недоступен с отдельного телефона.

## Основной сценарий

1. **Guest, оба раздела.** Нажмите «Показать всю коллекцию» / «Показать весь wish-list». При ширине 1440 px — прежняя таблица. Последовательно проверьте 1121, 1120, 1024, 768, 390 и 320 px. При ≤1120 px — список из четырёх полей: исполнитель, альбом, год, основной жанр. Структура: исполнитель, затем альбом, затем «год · жанр» в одной metadata-строке без года у правого края. Нет горизонтального переполнения страницы, текст и кнопки читаемы. Уточнение breakpoint согласуем по фактическому результату.
2. **Detail и клавиатура.** Нажатие/Enter на записи открывает bottom sheet, без изменения данных. Guest видит 9 публичных полей, без UUID, покупок и Ссылки Wish-list. Tab/Shift+Tab остаются в dialog. Закрытие кнопкой и Escape возвращает focus к записи. Длинное примечание и переносы помещаются/прокручиваются. При resize через breakpoint открытый detail закрывается, focus переходит в доступное представление.
3. **Общий поиск/сортировка.** Collection: поиск Alpha, две записи. Сортировка — компактная строка с подписью, select по содержимому и соседней кнопкой той же высоты; на 320 px допустим перенос группы, без выхода за экран. Выберите «Год альбома», переключите ↑/↓; порядок меняется. Переключитесь на desktop — активный heading соответствует mobile. Измените сортировку заголовком, вернитесь на mobile — select/направление соответствуют. «По умолчанию» возвращает Alpha First (1980), Alpha Second (1990); направление отключено. В Network resize не создаёт GET коллекций; критерии и порядок сохраняются. Повторите в Wish-list.
4. **CSV.** При одинаковых роли, поиске и сортировке скачайте на desktop и mobile — состав колонок, строки и порядок одинаковы. Guest: 9 колонок; owner Collection: 9; owner Wish-list: 10 со Ссылкой. UUID/покупки не экспортируются. Поиск Alpha экспортирует только две записи. Примечания с `=1+1`, кавычками, `;` и переносами сохраняются безопасно; формула не исполняется. После пустого поиска/«Очистить» скачивание недоступно.
5. **Owner и формы.** Войти тестовым паролем, заново показать список. Compact detail Collection содержит 12 пользовательских полей, включая дату DD.MM.YYYY/цену/магазин; Wish-list — 10 со Ссылкой. UUID не показан. Detail → Редактировать закрывает detail до открытия формы. Измените примечание, нажмите Отмена — focus исходной записи, PUT отсутствует. Повторите, просмотрите и подтвердите — список обновлён, detail не открывается повторно. Проверьте цену 0, пустые поля и дату 29.02.2024. Preview/кнопки не выходят за экран на 320/390 px. «Закрыть» в detail имеет те же height/padding, что Редактировать/Удалить/Добавить в коллекцию.
6. **Удаление и перенос.** Из detail отмените удаление — focus исходной записи. Подтвердите удаление — обновлённый список, focus в области результатов при исчезновении записи. Wish-list → detail → «Добавить в коллекцию»: одна форма, без вложенных modal. Отмена возвращает focus. Подтвердите перенос вымышленной Wish Alpha, проверьте обе коллекции. Успешный перенос не открывает detail повторно.
7. **Роль и stale state.** В одной вкладке откройте owner detail, во второй выйдите; вернитесь в первую. После проверки сессии detail закрыт/очищен, приватные результаты удалены. Снова покажите список — guest-поля без действий. Ни старый GET, ни resize не должны вернуть owner detail. Регрессии конфликтов If-Match, stale GET и неопределённых CRUD дополнительно покрыты автоматическими тестами; можно повторить двухвкладочный сценарий из acceptance 3A на стенде.
8. **Reports guest/owner, оба раздела.** «Сообщить об ошибке» доступно на desktop/mobile. Откройте форму: точный helper «Не указывайте пароли и личные данные», textarea, счётчик, Очистить/Отправить и × справа сверху с accessible label «Закрыть». Пустой/пробельный текст не отправляется. Emoji считается одним Unicode code point; 2000 разрешены, 2001 отключает отправку. ×/Escape и повторное открытие сохраняют draft. «Очистить» обнуляет draft/ошибку/счётчик, оставляет окно открытым. Отправьте вымышленный текст: loading, затем окно закрывается и на 5 секунд появляется «Сообщение отправлено». Снова откройте форму — draft пустой. В Network JSON содержит только text/section, ответ 201 только id. Во время отправки повторная отправка, очистка и закрытие отключены.
9. **Лимит и ошибки reports.** После трёх попыток с одного IP четвёртая получает 429 с Retry-After, текст остаётся в форме. Лимит общий между ролями/разделами, отдельный от login/GET: поиск продолжает работать. Для повторов перезапустите стенд. Для сетевой ошибки после открытия страницы включите Offline в DevTools, отправьте текст — он остаётся, показано отсутствие подтверждения; автоматического повтора нет. Верните Online. При ошибке окно остаётся открытым; ×/Escape не очищает draft. «Очистить» сбрасывает draft и ошибку, сохраняя dialog открытым. Лимит 50/час, сбои Google, потеря ответа после записи и post-write verification проверены автоматически без реальной таблицы.
10. **Desktop регрессии.** После возврата к ширине 1440 px сохраняются таблица, headings, поиск, CSV, login/logout и add/edit/delete/transfer. «Скачать csv» остаётся вне коллекции справа на уровне счётчика. Следующий presentation polish проверяется отдельно по сценарию 3C.

Reports стенда не сохраняются после перезапуска; публичного чтения и inbox нет. При успешной отправке тестируется тот же service с проверкой результата на in-memory repository. Реальная Google Sheets интеграция проверена только mock API, её подключение и контролируемая acceptance потребуют отдельного решения. Действия владельца — [подключение reports](bug-reports-setup.md).
